# 행사 데이터 보관과 삭제

Open Attendee의 현재 보관 동작과 운영자가 배포마다 정할 정책을 설명해요. 한국 행사에서 녹음·전사·외부 처리를 쓰는 경우 [녹음 자료 안내](recording-privacy-kr.md)도 확인해요. [검토 이슈 #84](https://github.com/jyje/open-attendee/issues/84)

## 데이터별 시작점, 만료와 삭제 경로

| 데이터 | 저장 위치와 시작점 | 현재 만료·삭제 방식 |
|---|---|---|
| 원본 녹음·음성 메모 | 업로드 완료 시 로컬 첨부 저장소 또는 S3 | 새 행사는 전사 후 원본 삭제가 기본이에요. 음성 구간을 저장할 때 **전사 후 음성 원본 보관**이 꺼져 있으면 삭제 작업이 등록돼요. 전사 실패나 감지된 음성이 없는 경우, 또는 보관을 선택한 경우에는 원본이 남아요. 자료의 **지우기** 또는 **행사 삭제**로 정리할 수 있어요. |
| 전사 | 처리된 음성 구간을 앱 서버 SQLite에 저장 | 원본만 자동 삭제돼도 전사는 유지돼요. 관련 음성 자료 또는 행사 자체를 삭제할 때 전사 구간도 제거돼요. |
| 사진·발표자료·참고자료 | 업로드 시 첨부 저장소에 파일이나 사진 처리본을 저장하고, 설명·문서 추출문 등은 SQLite에 저장 | 자료의 **지우기** 또는 **행사 삭제**로 파일과 추출문을 제거해요. 기존 사진을 새 흐림 처리본으로 바꾸면 이전 사진 객체와 축소판을 별도 작업으로 삭제해요. |
| 행사와 필기 | 행사를 만들거나 메모를 저장할 때 SQLite에 기록 | 필기는 블록별로 지울 수 있고 연결됐던 사진은 행사에 남아요. **행사 삭제**는 남은 행사 기록과 첨부를 제거해요. |
| 녹음 동의 기록 | 소유자가 동의 날짜와 방법을 등록할 때 SQLite에 저장 | 철회 시 철회 시각을 남기고 연결된 녹음과 파생 결과의 접근을 제한해요. **행사 삭제**에서 동의 기록을 함께 제거해요. |
| 요약·초안과 작업 기록 | 생성 결과 및 작업을 SQLite에 기록 | 과거 생성 결과도 행사와 함께 보관되고 **행사 삭제**에서 제거돼요. 연결된 입력을 개별 삭제해도 기존 생성 결과에 담긴 문장은 남을 수 있어요. 앱 밖으로 옮긴 파일은 받은 쪽에서 별도로 삭제해요. |
| 내보내기·외부 처리 사본 | 승인한 초안을 다운로드한 기기나 전달한 저장소, 설정된 모델 제공자의 처리 환경 | 다운로드 파일은 소유자 또는 수신자가 관리해요. 모델 입력의 보관 및 삭제는 사용하는 서비스 계약과 설정에 따라 처리해요. |
| 백업·스냅샷·이전 S3 버전 | 운영자가 백업을 시작하거나 저장소가 이전 버전을 보존할 때 | 배포 운영자가 대상, 만료, 복구 절차를 정해요. 버전 관리형 S3에서 앱은 현재 키를 삭제하며 이전 버전은 버킷에서 별도로 관리해요. [Amazon S3 객체 버전 삭제](https://docs.aws.amazon.com/AmazonS3/latest/userguide/DeletingObjectVersions.html) |

앱은 전사 후 원본 삭제를 작업으로 재시도해요. **원본 삭제 대기 중**이 계속 표시되면 운영자가 저장소 연결과 삭제 권한을 확인해요. 수동 자료·행사 삭제는 파일부터 지우므로 일부 파일만 처리된 상태에서 오류가 나면 연결과 권한을 복구한 뒤 같은 삭제를 재시도해요. 자료 삭제는 현재 파일 경로를, 행사 삭제는 행사 전체 첨부 경로를 대상으로 해요.

## 배포별 보관 정책

1. 어떤 목적으로 각 자료를 쓰는지, 종료를 무엇으로 판단하는지, 보관기한과 삭제 담당자를 정해요. 전사 후 원본을 계속 쓰는 행사는 보관을 선택한 이유와 원본을 다시 검토할 날짜도 정해요.
2. 행사 종료나 운영자가 정한 날짜에 원본, 전사 및 내보내기의 필요 여부를 확인해요. 필요한 자료만 정해진 기한까지 보관하고, 앱에서 개별 자료 또는 행사를 삭제해요. 개인정보 보호법이 적용되는 경우 보유기간 경과 등으로 불필요해진 개인정보의 파기 방법과 다른 법령에 따른 별도 보존 여부를 함께 확인해요. [개인정보 보호법 제21조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1029334901)
3. SQLite 데이터와 로컬 첨부 또는 S3는 함께 복구할 수 있게 백업 범위를 확인해요. 백업과 S3 이전 버전에 별도의 만료를 설정하고, 복구 과정에서 이미 삭제·철회된 자료가 다시 제공되지 않도록 복구본을 확인해요. 버전 관리형 S3의 이전 버전에는 별도의 만료 동작을 지정할 수 있어요. [Amazon S3 수명 주기 설정](https://docs.aws.amazon.com/AmazonS3/latest/userguide/intro-lifecycle-rules.html)
4. 자동 기간 만료가 필요한 배포는 대상과 시작점, 기간·예외를 먼저 정해요. 구현할 때는 앱의 SQLite와 첨부 파일 삭제를 같이 처리하고, 같은 작업을 다시 실행해도 안전하게 끝나는지와 백업에서 복구했을 때의 동작을 검증해요. 기간이 지난 자료를 찾고 삭제하는 절차는 현재 운영에서 수행해요.

운영자는 배포별 기준으로 데이터를 관리하고, 앱의 삭제 결과와 저장소·백업의 실제 파기 범위를 대조해요. 설정은 [배포 가이드](deploy.md)를 참고해요.
