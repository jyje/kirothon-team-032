# 행사 정리 시간과 결과 품질 검증

[#62](https://github.com/jyje/open-attendee/issues/62)에서 수작업과 앱 사용을 비교해요. 아래 절차로 측정할 수 있어요. 사람의 작업과 채점은 아직 진행 전이에요. 측정에는 실제 AI 제공자가 설정된 앱을 사용해요.

## 자료 준비

웹앱의 Python 의존성을 설치한 뒤 저장소 루트에서 실행해요.

```sh
uv run --project webapp/src --frozen python docs/validation/prepare_summary_benchmark.py /tmp/open-attendee-summary-benchmark
```

사례 A는 책 교환회, 사례 B는 수리 모임이에요. 사례별로 합성 필기 3개, 발표자료 2장, 안내판 사진 1장이 있어요. 참여자에게는 해당 사례의 파일과 아래 **과제**만 보여 주세요. 각 사례를 두 방식에서 똑같이 사용하고, 채점표는 채점자에게만 전달해요.

## 과제

자료를 바탕으로 참가 후기 초안을 Markdown 한 파일로 제출해요. 제목, 행사 개요, 참가 조건, 현장 안내가 있어야 해요. 각 사실 뒤에 근거를 붙여요. 근거는 `필기 1`, `슬라이드 2`, `안내판 사진`처럼 처음 보는 사람이 바로 찾을 수 있으면 돼요. 아직 정해지지 않은 정보는 미정으로 표시해요.

- 수작업에서는 일반 편집기로 자료를 읽고 초안을 작성해요. 생성형 AI는 사용하지 않아요.
- 앱을 사용할 때는 새 행사에 같은 필기, PPTX, 사진을 넣어요. 사진은 내용을 읽고 설명을 붙여 출처로 제공해요. 블로그 템플릿으로 초안을 만든 뒤 사실과 근거를 점검하고 승인·내보내기 해요.
- 두 방식 모두 파일을 받을 때 시작하고 Markdown 파일을 저장할 때 종료해요. 앱의 파일 등록, AI 대기, 근거 검토, 승인 시간을 포함해요. 공통 안내와 앱 로그인은 타이머를 시작하기 전에 마쳐요.
- 오류, 중단 또는 미완료가 있으면 경과 시간과 이유를 기록해요. 앱에서 표시하는 마지막 필기·자료 변경부터 승인까지의 시간은 보조 지표로 기록할 수 있어요.

## 실행 배정

같은 사람이 같은 사례를 두 번 읽는 일을 피하려고 사례와 순서를 교차해요. 네 배정을 모두 채우면 각 사례가 두 방식과 두 순서에 같은 횟수로 나타나요. 그보다 적은 인원으로 먼저 실행했다면 배정과 반복 수를 밝혀요.

| 배정 | 첫 번째 작업 | 두 번째 작업 |
|---|---|---|
| 1 | 수작업 · A | 앱 · B |
| 2 | 앱 · A | 수작업 · B |
| 3 | 수작업 · B | 앱 · A |
| 4 | 앱 · B | 수작업 · A |

## 채점과 기록

채점자에게는 방법 이름과 앱 공통 안내 문구를 가린 사본을 임의 순서로 전달해요. 표시된 근거와 사실은 그대로 두고, 채점 주체와 인원을 기록해요. 각 핵심 항목에 사실이 맞고 근거를 찾아 확인할 수 있으면 1점을 주세요. 출처가 뒷받침하지 않는 추가 사실, 필수 섹션 누락, 읽기 어려운 부분은 별도로 적어요.

| 항목 | A · 책 교환회 | B · 수리 모임 |
|---|---|---|
| 시간과 장소 | 일요일 14~16시, 주민센터 2층 (필기 1) | 토요일 10~12시, 생활문화센터 1층 (필기 1) |
| 정원과 접수 | 40명, 현장에서만 책 접수 (필기 2) | 24명, 선착순·무료 (필기 2) |
| 참가 조건 | 1인 3권까지, 교과서 제외 (슬라이드 1) | 1인 1개, 배터리 기기 제외 (슬라이드 1) |
| 접근 경로 | 서쪽 출입구 옆 엘리베이터 (슬라이드 2) | 남쪽 출입구 옆 경사로 (슬라이드 2) |
| 체크인 | 처음 15분, 서쪽 출입구 근처 데스크 (안내판 사진) | 처음 10분, 남쪽 출입구 근처 데스크 (안내판 사진) |
| 미정 내용 | 남은 책 기증처 미정 (필기 3) | 다음 모임 날짜 미정 (필기 3) |

한 줄에 실행 한 건을 기록해요. 참여자 이름 대신 익명 번호를 써요.

| 참여자 | 배정 | 순서 | 사례 | 방법 | 전체 분:초 | AI 대기 분:초 | 완주 | 근거 확인 점수 / 6 | 추가 오류·누락 |
|---|---|---|---|---|---|---|---|---|---|
| | | | | | | | | | |

참여자 수, 방법별 실행·완주 수, 사용한 앱 커밋과 모델, 브라우저·기기, 대기 시간 포함 여부를 결과에 기록해요. 방법별 전체 시간과 점수의 중앙값을 보고하고, 30분 이내 완주 횟수와 중단·오류도 함께 제시해요. 자료가 짧은 합성 사례라는 점과 소규모 표본의 한계를 밝혀요.
