# 실기기 장시간 녹음 검증

[#68](https://github.com/jyje/open-attendee/issues/68)의 테스트 절차와 현재 증거를 기록해요. 데스크톱과 모바일의 물리 마이크 결과를 아래 표에 추가해요.

## 자동 검증에서 확인한 동작

| 확인한 내용 | 범위와 결과 |
|---|---|
| 녹음 시작, 화면 이동, 부분 저장 | Chromium의 합성 마이크에서 확인했어요. 앱 안에서 **자료**를 떠나면 마이크가 닫혔고, **자료**로 돌아와 기록된 부분을 저장했어요. |
| 긴 첨부 파일 업로드 | 3시간짜리 합성 WAV를 인그레스 경유로 올렸어요. 녹음용 업로드 크기 설정에서 저장한 뒤 같은 파일을 내려받고 SHA-256이 일치하는 것을 확인했어요. [업로드 검증 PR #69](https://github.com/jyje/open-attendee/pull/69) |
| 저장 중 네트워크 중단 | Chrome에서 서버가 업로드를 저장한 다음 성공 응답을 끊었어요. **녹음 저장**을 다시 눌러도 파일이 하나만 남았어요. [#79](https://github.com/jyje/open-attendee/issues/79) |
| 오디오 트랙 중단 | Chrome에서 합성 트랙을 종료했어요. 녹음 중단이 표시됐고, 남은 부분이 있으면 저장할 수 있었어요. 빈 녹음은 다시 시작할 수 있었어요. [#81](https://github.com/jyje/open-attendee/issues/81) |

중단 안내를 추가한 [PR #82의 브라우저 CI](https://github.com/jyje/open-attendee/actions/runs/44086308299)가 통과했어요. 자동화 시나리오는 [녹음 브라우저 테스트](../../webapp/frontend/e2e/recording.spec.ts)에서 볼 수 있어요. 실기기에서 화면을 잠그거나 오랫동안 마이크를 켜 두는 동작은 아래 순서로 확인해요.

## 실기기 테스트 순서

1. 녹음과 전사가 켜진 HTTPS 테스트 환경에서 별도 행사를 만들어요. 기기, OS·브라우저 버전, 테스트 앱 커밋, 저장소 종류를 기록해요. 주변 대화 대신 직접 준비한 테스트 음성을 사용하고, 자료 화면에서 시험용 동의를 등록해요. 배포는 [녹음과 전사 설정](../deploy.md#브라우저-녹음과-업로드-크기)을 참고해요.
2. 데스크톱과 모바일의 실제 마이크로 연속 녹음을 각각 실행해요. 프로젝트의 3시간 행사 사용 사례에 맞춰 시작, 중간, 종료 직전에 구분되는 소리나 테스트 문장을 남겨요. 실제 녹음 시간과 파일 크기를 기록해요. 저장·다운로드 후 재생해 세 지점의 음성이 들어 있는지 확인해요.
3. 짧은 별도 녹음을 각각 시작해 화면 잠금·해제, 다른 브라우저 탭 이동·복귀, 마이크 연결 해제, 저장 중 네트워크 끊김·복구를 반복해요. 화면 이동과 기기 잠금은 별개로 기록해요. 중단 여부, 화면 안내, 중단 전 기록과 중단 후 녹음의 재생 여부를 확인해요. 다시 저장할 때 행사 목록과 첨부에 중복이 없는지도 확인해요. 연결을 끊을 수 있는 입력 장치가 없는 경우 그 시나리오를 다른 기기에서 확인해요.
4. 처리 완료 후 시험 자료를 삭제해요. 이슈에는 결과 표, 재현 가능한 조작 순서, 화면 메시지를 남겨요. 테스트 자체의 녹음 파일을 공유할 필요가 없는 경우 재생 확인 결과만 기록해요.
