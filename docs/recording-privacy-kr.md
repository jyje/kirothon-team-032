# 한국 행사에서 녹음과 전사 자료를 다룰 때

2026년 11월 17일 기준으로 한국 행사에 적용할 법령과 Open Attendee의 기능을 대조했어요. 개별 행사의 규칙과 운영 주체, 실제 저장소·모델 제공자 계약에 따라 판단할 내용이 달라져요. [검토 이슈 #85](https://github.com/jyje/open-attendee/issues/85)

## 녹음할 범위

- 직접 참여한 대화는 통신비밀보호법의 공개되지 않은 타인 간 대화를 제3자가 녹음하는 경우와 법적 판단이 달라요. 앱에서 녹음하기 전 참석자에게 목적과 범위를 알리고, 행사 주최자가 정한 촬영·녹음 기준도 확인해요. 음성이나 발언으로 개인을 알아볼 수 있다면 처리 주체와 수집·이용 근거도 확인해요. 동의를 근거로 쓸 때는 목적, 항목, 보유·이용 기간, 거부권과 거부 시 불이익을 알려야 해요. [대법원 2020도1007](https://www.law.go.kr/LSW/precInfoP.do?precSeq=230871) · [개인정보 보호법 제15조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1006183947)
- 옆자리 대화처럼 녹음자가 참여하지 않은 대화가 섞일 수 있으면 녹음 범위를 조정하거나 중지해요. 행사 참석 인원만으로 대화의 공개 여부를 판단하기는 어려워요. 발언자의 의사와 기대, 접근 제한, 장소와 청중 등 구체적 사정을 함께 봐요. [통신비밀보호법 제14조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1035328205) · [대법원 2020도1007](https://www.law.go.kr/LSW/precInfoP.do?precSeq=230871)

## 앱에서 자료가 이동하는 경로

| 동작 | 현재 앱 동작 | 행사 운영자가 확인할 내용 |
|---|---|---|
| 기록과 업로드 | 행사 동의에서 전원 고지·동의, 날짜와 방법을 기록할 수 있음, 동의 범위 밖 공개 금지를 확인해요. 브라우저 녹음을 저장하면 앱 서버로 올라가고, 첨부는 로컬 저장소 또는 설정된 S3에 저장돼요. | 참석자에게 알린 목적과 범위, 거부할 방법, 행사 규칙, 앱 운영 주체와 데이터 저장 위치를 확인해요. 앱은 기록을 입력하는 소유자의 확인을 저장해요. |
| 전사 | `faster_whisper` 설정에서는 앱 서버에서 음성을 읽어 텍스트로 바꾸고, 전사 결과를 서버 SQLite에 저장해요. | 앱 서버와 S3가 각각 어디에 있는지 확인해요. 전사 결과의 보관 기간과 열람 범위를 정하고, 들어 있으면 곤란한 발언의 처리 절차를 마련해요. |
| AI 요약·초안 | AI 생성 또는 근거 판정을 요청하면 설정된 모델 제공자에게 텍스트 프롬프트가 전달돼요. 유효한 전사, 필기, 문서 추출문, 사진 설명이 입력에 들어갈 수 있어요. | 제공자의 처리 목적과 실제 설정에 따라 업무위탁인지 제3자 제공인지 판단하고, 제공자·재위탁자, 처리 국가, 보관 및 추가 이용 조건을 확인해요. |
| 공유·공개 | 초안 승인 뒤 Markdown이나 HTML을 내려받을 수 있어요. 앱 승인은 초안 검토 상태를 기록해요. | 공개 전 인용문과 개인정보, 제공 목적·받는 사람·공개 범위, 행사 자료의 이용 권한을 확인해요. 공개 후 회수나 삭제 요청을 처리할 연락 창구를 정해요. |
| 철회·삭제 | 소유자가 앱에서 동의를 철회하면 연결된 녹음과 전사, 그 음성을 입력으로 사용한 요약·초안의 접근을 제한해요. 자료나 행사를 지우는 기능은 별도로 있어요. | 당사자의 처리정지·철회 요청을 어디에서 받는지 정해요. 앱에 저장된 데이터, 모델 제공자와 백업에 있는 사본, 이미 받은 내보내기 파일 각각의 조치와 사유를 기록해요. |

관련 구현은 [녹음 동의](../webapp/src/open_attendee/consent.py), [전사 설정](deploy.md#cpu-전사-켜기), [모델에 넣는 출처](../webapp/src/open_attendee/pipeline/sources.py), [승인·내보내기](../webapp/src/open_attendee/drafts.py)에서 확인할 수 있어요.

## 외부 제공과 국외 처리

- 처리위탁에 해당하는 경우 위탁 목적과 보호조치를 문서로 정하고, 위탁 업무와 수탁자를 정보주체가 확인할 수 있게 해요. 제3자 제공에 해당하면 제공 근거와 목적 범위를 확인해요. 제공에 관한 동의가 필요하면 제공받는 자, 목적, 항목, 보유·이용 기간과 거부에 관한 사항을 알리는 절차를 마련해요. [개인정보 보호법 제17·18조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1029334879) · [제26조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034516495)
- 개인정보를 국외에 제공하거나, 국외에서 위탁 처리·보관하면 제28조의8의 이전 근거와 보호조치를 확인해요. 별도 동의를 근거로 이전할 때는 국가, 이전 방법과 시기, 수신자와 연락처, 항목, 목적과 보유기간, 거부 방법과 효과를 미리 알려야 해요. 서버 위치, S3 설정, 모델의 실제 처리 위치와 재위탁 조건을 배포마다 확인해요. [개인정보 보호법 제28조의8](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334869) · [개인정보보호위원회 생성형 AI 안내서](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS217&mCode=G010030040&nttId=11439)
- 앱의 행사 동의에는 제공자·이전 국가·보유기간을 적는 별도 필드가 없어요. 배포 운영자는 외부 처리 경로를 먼저 확인하고, 필요한 고지·동의 또는 그 밖의 적용 근거를 정해요. 허용 범위를 확인하기 전에는 해당 자료의 모델 전송이나 공개를 보류하고 행사 필기와 로컬 전사를 쓸 수 있어요.
- 앱 내 접근 제한과 개인정보 파기를 별도로 확인해요. 운영자는 개인정보가 불필요해진 시점의 파기 절차와 동의 철회 후 조치를 정해요. 데이터 종류별 보관과 파기 범위는 [#84](https://github.com/jyje/open-attendee/issues/84)에서 추적해요. [개인정보 보호법 제21조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334901) · [제37조](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900078400)
