## 2. 거버넌스

### 대회 규칙에서 가져온 4항목

| 항목 | 내용 | 우리가 할 일 |
|---|---|---|
| 원본 작업 | 행사 기간에 만든 작업만 인정해요. 기존 프로젝트는 안 돼요 | git 이력으로 작업 시점을 남겨요. 가져온 코드는 출처와 범위를 적어요 |
| 지식재산 | 저작권은 참가자에게 있어요. 제출하면 주최측이 프로젝트를 소개할 수 있어요 | 공개해도 되는 것만 올려요. `LICENSE`를 유지해요 |
| 행동 강령 | **AWS 행동강령**을 따라요. 서로 존중하기(차별, 괴롭힘, 위협 금지), 정직하게 참여하기(정확한 정보로 등록, 본인 명찰만 사용), 운영 지침 따르기(허가 없는 홍보 금지). 위반하면 참여 중단, 퇴장, 이후 AWS 행사 참여 제한, 콘텐츠 삭제가 있을 수 있어요 | 팀 대화와 PR 코멘트에 적용해요. 문제를 보거나 겪으면 현장 운영진이나 aws-events-security-concerns@amazon.com에 알려요 |
| 실격 | 규칙 위반, 표절 코드, 제출 요건 미충족은 실격이에요 | 아래 체크리스트로 점검해요 |

### 외부 코드와 디자인

- 가져온 자료는 출처, 버전, 라이선스를 남겨요. 예: `docs/references/cloudscape/` (Apache-2.0, `LICENSE`와 `NOTICE` 포함).
- 출처를 모르는 코드는 넣지 않아요.

### 작업 규칙 (`AGENTS.md`)

- `main`에 직접 push하지 않아요. `crew/<영역>/<주제>` 브랜치에서 PR을 열어요.
- PR 본문 첫 줄에 `Opened by: <이름>`을 적어요. Bot과 사람 모두 해당해요.
- 커밋 제목은 `<gitmoji> <type>(<domain>): <title>`.
- Kiro Crew Bot의 커밋은 서명하지 않아요. 그래서 PR로만 올려요.
- 제출 전에 마지막 커밋을 push하고 PR 링크를 제출 폼에 넣어요.

### AI 사용 기록

- Bot과 Kiro가 만든 결과는 사람이 검토하고 병합해요.
- 사용 내역은 `BUILD_REPORT.md`에 단계별로 남겨요.

## 3. 보안 유의사항

### 비밀 정보

- API 키, 비밀번호, 토큰, `.env`는 커밋하지 않아요.
- `.gitignore`가 `.env`, `.env.*`, `*.pem`, `*.key`를 막아요. `.env.example`만 올라가요.
- `.env.example`에는 가짜 값만 둬요.
- 키가 한 번이라도 커밋되면 **즉시 폐기하고 새로 발급**해요. git 이력 삭제만으로는 부족해요.
- 커밋 메시지와 PR 본문에 로컬 경로, 토큰, 이메일을 쓰지 않아요.

### 공개 저장소

- 저장소가 Public이라 모든 파일이 보여요. 개인정보, 내부 주소, 로그를 올리기 전에 확인해요.
- `.worktrees/`, `.claude/`, `.DS_Store` 같은 작업 흔적이 올라가지 않는지 `git status`로 봐요.
- 데모 영상은 저장소에 올리지 않고 링크로만 적어요.
- 참가자 개인정보(이름, 소속, 학교, 연락처)는 README와 `BUILD_REPORT.md`에 필요한 만큼만 적어요.
- 참여 확정 페이지의 개인 링크, 이름, 소속은 저장소에 쓰지 않아요. 이 문서도 가려 두었어요.

### 애플리케이션

- 사용자 입력은 서버에서 검증해요.
- 세션과 메모 데이터는 소유자만 읽고 써요. 소유자 격리(Property 18) 테스트를 유지해요.
- 의존성은 알려진 취약점을 점검하고, 쓰지 않는 패키지는 빼요.
- Docker 이미지와 Helm 값에 비밀 정보를 굽지 않아요. 시크릿은 환경 변수나 Kubernetes Secret으로 넣어요.
- AWS 자격 증명은 최소 권한으로 쓰고, 장기 키 대신 SSO나 역할을 써요.
- 모델 공급자 키(Bedrock, OpenAI)는 `.env`로만 넣어요. Codex 토큰은 Codex가 보관하게 하고 직접 다루지 않아요.
